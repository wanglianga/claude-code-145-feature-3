# 社区长者智能手环告警家属确认与上门处置平台

面向社区独居老人照护场景的告警处置系统（前端单页应用）。手环上报跌倒、心率异常、长时间静止、离家未归、设备离线等告警后，平台按**告警类型、最近活动轨迹、历史误报、家属联系方式、社区值班人员**自动生成处置流程；家属端确认，社区端上门处置，全程（告警 → 确认 → 上门 → 处置 → 就医 → 回访）记录在同一事件内，结案后生成复盘报告并沉淀**照护画像**。

## 技术栈

React 18 · TypeScript · Zustand · React Router · Ant Design 5 · Vite

## 功能地图

| 模块 | 说明 |
| --- | --- |
| 告警工作台 | 待处理/升级/已结案统计，事件列表筛选，模拟手环上报 |
| 事件处置 | 自动生成的处置流程（含每步依据）、升级情形（家属超时/电话无人接/低电/夜间浴室/上门无人开门/联动物业/联动120）、家属与社区双端操作、全程时间线 |
| 老人档案与设备 | 姓名、住址、慢病、紧急联系人、常用活动范围、设备电量、佩戴习惯、午睡时段、当前阈值（只读）；阈值不可直接修改，须走审批 |
| **误报阈值调整** | **汇总午睡时段、心率、活动轨迹与家属确认记录 → 医生/社区审批（必填审批人、原因、依据事件）→ 调整后进入观察期，跟踪误报是否下降、真实风险有无漏报，漏报自动回退；变更记录永久保留，事件详情可回看「当时为何降低或延后告警」** |
| 结案复盘 | 误报原因、设备调整建议（按原因自动生成）、家属响应时长、社区处置时效；事件分类：设备误报 / 照护缺口 / 真实风险 |
| 照护画像 | 结案自动沉淀：连续无人响应、频繁离线、多次上门无人在家 → 画像标签与风险等级；社区可调整巡访频次、设备维护、家属提醒方式；卡片内嵌阈值调整史 |
| 家属端门户 | 确认误报 / 请求电话核实 / 要求上门 / 直接拨打120，查看事件进展、历史复盘与老人阈值调整知情记录 |

## 本地启动

```bash
npm install
npm run dev        # http://localhost:5173
```

生产构建与预览：

```bash
npm run build
npm run preview    # http://localhost:4173
```

端到端流程自测（告警→超时升级→家属响应→上门→物业/120→就医→回访→结案→画像沉淀，以及午睡误报汇总→阈值审批→观察期→漏报自动回退/通过生效→时点回看，共 62 项断言）：

```bash
npm run test:flow  # 输出 ALL CHECKS PASSED 即通过
```

## 验证方式（本题核心流程）

以下验证均已在本地实际执行：`npm run build` 构建通过；`npm run test:flow` 62 项断言全部通过；`vite preview` 下页面正常返回 HTTP 200。

1. **登录社区端**（community/123456）→ 工作台可见 1 条进行中的「跌倒告警」（王秀兰，浴室，夜间，等级：紧急）与 1 条「设备离线」上门中事件，另有 2 条已结案事件（真实风险、设备误报）。
2. **打开跌倒事件** → 中部为自动生成的处置流程（通知家属 → 家属确认 → 网格员上门 → 联动物业/120 → 回访结案，每步标注生成依据）；左侧为老人档案（慢病、联系人、轨迹、门禁、钥匙托管、上次回访）。
3. **家属超时升级** → 点击顶栏「演示时间快进 +5分钟」（或等待 3 分钟）→ 事件出现「家属超时未响应」升级标记，时间线自动追加记录。
4. **家属确认** → 退出登录，改用 family/123456 进入家属端 → 对告警执行「要求上门查看」（也可在社区端事件页用「家属端操作模拟」面板操作）。
5. **社区上门** → 回到社区端：派单上门（自动匹配就近网格员）→ 记录到达 → 记录结果；选择「无人开门」会触发升级并解锁「联动物业开门 / 使用托管钥匙」；选择「需医疗处置」后呼叫 120 并记录就医结果。
6. **回访结案** → 记录回访 → 结案并选择事件分类（设备误报需选误报原因）→ 自动生成复盘报告：误报原因、设备调整建议、家属响应时长、社区处置时效。
7. **画像沉淀** → 进入「照护画像」页：该老人的误报/缺口/风险计数、家属未响应、上门无人等指标已更新，画像标签与风险等级自动重算，可调整巡访频次、设备维护、家属提醒方式。
8. **午睡误报汇总** → 进入「误报阈值调整」页（默认选中王秀兰）：可见近 7 天 **3 起午睡时段（13:00-14:30）长时间静止误报**汇总——误报时刻、午睡心率（62-70bpm 平稳，符合睡眠特征）、活动轨迹/告警位置（卧室、沙发）、家属王莉的逐条确认留言；系统据此建议「仅午睡时段将静止告警延后 30 分钟，心率/跌倒灵敏度不变」。
9. **阈值调整审批（留痕）** → 点「按建议发起阈值调整审批」：表单默认填入静止阈值 60 分钟、午睡延后 30 分钟、7 天观察期、3 条依据事件；**审批人（陈医生/社区医生）与调整原因必填**。提交后档案阈值立即更新，记录状态为「观察期中」，可在下方变更记录表查看调整前后取值、审批人、原因与依据事件。
10. **调整后继续观察** → 在观察期卡片点「模拟午睡误报（家属确认）」（时间自动快进到午睡时段），新静止告警的处置流程明确标注按延后阈值 **90 分钟**（60+30）判定；再点「模拟午睡真实异常被漏报」（家属称叫不醒→上门发现需医疗），观察区出现红色漏报提示。
11. **观察评估与自动回退** → 点「完成观察评估」：因观察期发现真实异常，系统**自动回退**至调整前阈值（60→45 分钟），记录转为「已回退」并保留回退人、回退原因与观察结论；之后再模拟午睡静止告警，流程恢复按 45 分钟默认阈值判定。
12. **真实异常回看** → 打开第 10 步那起「需医疗」事件，左侧新增「告警判定时的阈值策略」卡：即使该调整已回退，仍可回看当时生效的变更编号、审批人、**当时为何降低/延后告警的原因**与回退信息——满足后续照护评估追责与复盘需要。
13. **观察通过与人工回退** → 切换到周淑珍可演示「无误报无漏报 → 持续生效」；切换到李建国可演示「人工回退（医生复查房颤史不宜放宽）」，回退原因同样必填且永久留痕。家属端（family/123456）可在左侧查看老人阈值调整的知情记录（只读）。
14. **模拟新告警** → 工作台「模拟手环上报」可任选老人、告警类型（跌倒/心率异常/长时间静止/离家未归/设备离线）与位置，验证不同告警生成的差异化处置流程（如低电量老人会追加「设备维护」步骤，浴室/夜间自动升级）。

## 演示说明

- 家属响应超时阈值演示设为 **3 分钟**（顶栏「演示时间快进」可立即触发）。
- 王秀兰种子数据已内置 **午睡时段 13:00-14:30**、午睡心率采样与 **3 起午睡静止误报**（EV-0990/0991/0992，家属王莉均确认误报）；张桂芳内置一条 12 天前经陈医生审批、观察期通过后持续生效的阈值变更（TC-0001）。
- 「误报阈值调整」页的「模拟午睡误报/真实异常」按钮会自动把演示时间快进到下一个午睡时段，无需手动等待。
- 数据为内存态（Zustand），刷新页面后重置为种子数据。
- 项目类型为前端单页应用，按题目约束不提供 Swagger/OpenAPI。
