# 社区长者智能手环告警家属确认与上门处置平台

面向社区独居老人照护场景的告警处置系统（前端单页应用）。手环上报跌倒、心率异常、长时间静止、离家未归、设备离线等告警后，平台按**告警类型、最近活动轨迹、历史误报、家属联系方式、社区值班人员**自动生成处置流程；家属端确认，社区端上门处置，全程（告警 → 确认 → 上门 → 处置 → 就医 → 回访）记录在同一事件内，结案后生成复盘报告并沉淀**照护画像**。

## 技术栈

React 18 · TypeScript · Zustand · React Router · Ant Design 5 · Vite

## 功能地图

| 模块 | 说明 |
| --- | --- |
| 告警工作台 | 待处理/升级/已结案统计，事件列表筛选，模拟手环上报 |
| 事件处置 | 自动生成的处置流程（含每步依据）、升级情形（家属超时/电话无人接/低电/夜间浴室/上门无人开门/联动物业/联动120）、家属与社区双端操作、全程时间线 |
| 老人档案与设备 | 姓名、住址、慢病、紧急联系人、常用活动范围、设备电量、佩戴习惯、告警阈值（可在线调整）、午睡延后时段 |
| 误报分析与阈值审批 | 家属多次确认午睡静止误报后，自动汇总**午睡时段、静息心率、活动轨迹、家属确认记录**；医生/社区审批调整，**保留审批人、原因、依据与前后阈值快照**，进入观察期持续跟踪误报是否下降、真实风险是否遗漏；可回退，记录长期留存供照护评估回看 |
| 结案复盘 | 误报原因、设备调整建议（按原因自动生成）、家属响应时长、社区处置时效；事件分类：设备误报 / 照护缺口 / 真实风险 |
| 照护画像 | 结案自动沉淀：连续无人响应、频繁离线、多次上门无人在家 → 画像标签与风险等级；社区可调整巡访频次、设备维护、家属提醒方式 |
| 家属端门户 | 确认误报 / 请求电话核实 / 要求上门 / 直接拨打120，查看事件进展与历史复盘 |

## 本地启动

```bash
npm install
npm run dev        # http://localhost:5173
```

生产构建与预览：

```bash
npm run build
npm run preview    # http://localhost:4173
```

端到端流程自测（告警→超时升级→家属响应→上门→物业/120→就医→回访→结案→画像沉淀，以及午睡误报汇总→阈值审批→观察期跟踪→真实风险回看→回退，共 63 项断言）：

```bash
npm run test:flow  # 输出 ALL CHECKS PASSED 即通过
```

## 验证方式（本题核心流程）

以下验证均已在本地实际执行：`npm run build` 构建通过；`npm run test:flow` 63 项断言全部通过；`vite preview` 下页面正常返回 HTTP 200。

1. **登录社区端**（community/123456）→ 工作台可见 1 条进行中的「跌倒告警」（王秀兰，浴室，夜间，等级：紧急）与 1 条「设备离线」上门中事件，另有 5 条已结案事件（真实风险、设备误报，含 3 起午睡静止误报）。
2. **打开跌倒事件** → 中部为自动生成的处置流程（通知家属 → 家属确认 → 网格员上门 → 联动物业/120 → 回访结案，每步标注生成依据）；左侧为老人档案（慢病、联系人、轨迹、门禁、钥匙托管、上次回访）。
3. **家属超时升级** → 点击顶栏「演示时间快进 +5分钟」（或等待 3 分钟）→ 事件出现「家属超时未响应」升级标记，时间线自动追加记录。
4. **家属确认** → 退出登录，改用 family/123456 进入家属端 → 对告警执行「要求上门查看」（也可在社区端事件页用「家属端操作模拟」面板操作）。
5. **社区上门** → 回到社区端：派单上门（自动匹配就近网格员）→ 记录到达 → 记录结果；选择「无人开门」会触发升级并解锁「联动物业开门 / 使用托管钥匙」；选择「需医疗处置」后呼叫 120 并记录就医结果。
6. **回访结案** → 记录回访 → 结案并选择事件分类（设备误报需选误报原因）→ 自动生成复盘报告：误报原因、设备调整建议、家属响应时长、社区处置时效。
7. **画像沉淀** → 进入「照护画像」页：该老人的误报/缺口/风险计数、家属未响应、上门无人等指标已更新，画像标签与风险等级自动重算，可调整巡访频次、设备维护、家属提醒方式。
8. **午睡误报汇总**（本题核心）→ 进入「误报分析与阈值审批」页：王秀兰近 10 天 **3 起午睡时段（13:00-14:30）长时间静止告警**已自动汇总，页面并列展示午睡时段、午睡静息心率 62-69bpm、告警前后活动轨迹、家属 3 次确认记录（含留言与平均 7 分钟确认耗时），并给出系统调整建议（午睡时段静止阈值 45→75 分钟、告警延后、心率兜底、14 天观察期）。
9. **阈值审批调整** → 点击「发起阈值调整审批」：可修改午睡静止阈值与午睡时段，**必须填写审批人（社区医生陈医生/值班员）、调整原因、审批意见与观察期**；保存后生成带编号的变更记录（保留前后阈值快照与 3 起依据事件链接），新阈值立即生效，依据事件时间线自动追加关联记录。
10. **调整后持续观察** → 用「演示时间快进」到下一个 13:30，工作台模拟上报「长时间静止（家-卧室）」：告警降为一般并进入午睡延后处理（暂不打扰家属，时间线说明心率兜底），而同时段上报「心率异常」仍为紧急、立即通知家属。结案后事件自动归入变更记录：误报计入「误报是否下降」，真实风险计入「真实风险是否遗漏」。
11. **真实异常回看与回退** → 观察期内结案一起真实风险事件后，变更记录红色提示「发现真实风险，请回看」；打开该事件，顶部横幅显示当时生效的阈值调整（审批人、原因、前后值），说明**为何降低/延后告警**；社区可在审批页「回退阈值」，阈值恢复调整前快照，而审批人、原因、依据、观察结论永久保留给后续照护评估。
12. **档案联动** → 「老人档案与设备」页可见午睡延后时段标记；抽屉内引导降低/延后告警走审批流程（普通建档参数仍可直接维护）。
13. **模拟新告警** → 工作台「模拟手环上报」可任选老人、告警类型（跌倒/心率异常/长时间静止/离家未归/设备离线）与位置，验证不同告警生成的差异化处置流程（如低电量老人会追加「设备维护」步骤，浴室/夜间自动升级）。

## 演示说明

- 家属响应超时阈值演示设为 **3 分钟**（顶栏「演示时间快进」可立即触发）。
- 午睡延后告警：审批设置午睡时段后，时段内静止告警降为一般并延后至午睡结束（快进跨过午睡结束时刻即自动补发家属通知）；心率异常不受延后影响。
- 数据为内存态（Zustand），刷新页面后重置为种子数据。
- 项目类型为前端单页应用，按题目约束不提供 Swagger/OpenAPI。
